# piomo-primary-agents

senpi(pi) TUI에서 메인 에이전트 네 명을 Tab 한 번으로 바꿔 쓰게 해 주는 확장입니다.
Sisyphus, Hephaestus, Prometheus, Atlas가 그 네 명이고, 이 확장은 다음을 합니다.

- 입력창에서 Tab을 누르면 다음 에이전트로 바뀝니다.
- 입력창 아래에 지금 에이전트, 모델, 추론 단계를 한 줄로 보여 줍니다.
- 에이전트마다 마지막으로 고른 모델을 기억합니다.
- Prometheus와 Atlas는 쓸 수 있는 파일과 도구를 제한합니다.
- Prometheus에게 말로 계획을 부탁하면 정식 계획 검토(ulw-plan)로 이어집니다.

작업자(자식) 세션에서는 아무것도 하지 않습니다. 메인 TUI 세션에서만 움직입니다.

English: [README.md](README.md) · WinForms 스위처 보관 절차: [docs/winforms-archive.ko.md](docs/winforms-archive.ko.md)

## 사용법

### 카드 1. 에이전트 바꾸기: Tab

**할 일:** 입력창에서 Tab을 누릅니다.
**결과:** Sisyphus → Hephaestus → Prometheus → Atlas 순서로 다음 에이전트가 되고, 아래 라벨이 바로 바뀝니다. 쓸 수 없는 에이전트는 건너뛰고 그 이유를 알려 줍니다.

Tab이 **자동완성으로 남는** 경우가 있습니다.

| 상황 | Tab이 하는 일 |
|---|---|
| 자동완성 목록이 열려 있음 | 고른 항목 완성 |
| 커서 앞 단어가 `/` `.` `~` `@`로 시작하거나, `/`나 `\`를 품거나, `C:` 같은 드라이브로 시작 | 경로·명령어 완성 |
| 응답 중이거나 전환이 진행 중 | 아무것도 안 바꾸고 "응답 중에는 에이전트를 바꿀 수 없어요" 한 번 표시 |
| 그 밖의 모든 경우 | 에이전트 전환 |

끝에 점이 붙은 말이나 `10:30` 같은 시각은 경로로 보지 않으므로 Tab이 전환합니다.

### 카드 2. 라벨 읽기

**할 일:** 입력창 바로 아래 줄을 봅니다.
**결과:** 이런 모양이 보입니다.

```
▌ Hephaestus  gpt-6.1-sol-fast · medium                Tab 전환
```

- 막대와 이름은 에이전트 색입니다(Sisyphus 청록, Hephaestus 주황, Prometheus 보라, Atlas 초록).
- 이름 뒤는 모델 id와 추론 단계입니다.
- 모델 뒤에 `(대기)`가 붙으면 모델 변경이 다음 턴에 적용된다는 뜻입니다.
- 화면이 좁으면 오른쪽 `Tab 전환` 안내가 먼저 사라지고, 그다음 모델 id가 `…`로 줄어듭니다.

### 카드 3. 이름으로 바꾸기: `/agent`

**할 일:** `/agent`를 입력합니다. 이름을 바로 붙여도 됩니다(`/agent atlas`, 대소문자 무관).
**결과:** 이름이 없으면 쓸 수 있는 에이전트 목록이 뜨고, 고르면 바뀝니다. 모르는 이름이면 "알 수 없는 에이전트예요"와 함께 쓸 수 있는 이름을 알려 줍니다.

### 카드 4. 에이전트별 모델 기억

**할 일:** 어떤 에이전트로 있는 동안 `/model`로 모델을 고릅니다.
**결과:** 그 모델이 그 에이전트 몫으로 저장되고, 다음에 그 에이전트로 돌아오면(새 세션 포함) 같은 모델로 시작합니다.

저장 위치는 에이전트 디렉터리 아래입니다.

- 기억: `<agentDir>/primary-agents/memory/<에이전트id>.json` (이 확장만 씁니다)
- 레인과 핀: `<agentDir>/primary-agents/roster.json` (상황판만 씁니다)

기억이 없으면 레인 기본값을 씁니다. Sisyphus와 Atlas는 daily-normal, Prometheus는 daily-heavy, Hephaestus는 geeky-normal입니다. 상황판에서 핀을 바꾸거나 기억을 초기화하면 roster의 `rev`가 올라가고, 예전 기억 파일은 무시됩니다.

### 카드 5. Prometheus에게 계획 맡기기

**할 일:** Prometheus로 바꾼 뒤 그냥 말로 부탁합니다. 예: "로그인 화면 개편 계획 짜 줘".
**결과:** 명령어 없이도 정식 계획 흐름(ulw-plan)과 검토가 열립니다. `/skill:ulw-plan`을 직접 쳐도 됩니다.

실행(ulw-execute) 뒤에도 소유자가 새 계획을 요청하면 같은 세션에서 검토할 수 있습니다. `plan-review-unlock` 정책이 적용된 환경에서는 추가 게이트 어댑터가 필요하지 않고, 다시 실행해도 검토를 잠그지 않습니다. 명시적인 계획 요청과 실제 계획 파일은 여전히 필요합니다. 이전 실행 잠금 정책을 사용하는 환경의 선택적 어댑터는 아직 실사용 설치 전이며, 설치는 소유자 승인 단계(todo 16)에서만 합니다. 설치, 제거, 되돌리기, omo 업데이트 뒤 다시 적용하는 방법: [docs/gate-adapter.ko.md](docs/gate-adapter.ko.md)

### 카드 6. Prometheus와 Atlas의 제한 알기

**할 일:** 없음. 알아 두기만 하면 됩니다.
**결과:**

- **Prometheus**는 `<작업폴더>/.omo/` 아래 `.md` 파일만 고칠 수 있습니다. 셸은 읽기 명령과 계획 생성 스크립트만 되고, 위임도 읽기 전용 에이전트(explore, librarian, oracle, plan-consultant, plan-reviewer)에게만 됩니다.
- **Atlas**는 `<작업폴더>/.omo/` 아래만 고칠 수 있습니다.
- Sisyphus와 Hephaestus는 제한이 없습니다.

알려진 빈틈(일부러 남긴 것):

- 제한은 도구 단위입니다. eval 셀 안에서 코드가 직접 파일을 쓰면 막지 못합니다.
- Atlas의 bash는 열려 있습니다. bash로 하는 쓰기는 막지 않습니다.

## 설치와 제거

### 카드 7. 설치

**할 일:** 에이전트 디렉터리의 `settings.json`에서 `packages` 배열에 이 저장소 경로를 넣고, senpi를 새로 엽니다.

```json
{
  "packages": [
    "C:\\Users\\USER\\orca\\projects\\piomo-primary-agents"
  ]
}
```

**결과:** 새 세션 입력창 아래에 라벨이 보입니다. `dist/`가 저장소에 들어 있으므로 따로 빌드할 필요는 없습니다.

`settings.json`을 고치기 전에 사본을 하나 떠 두세요.

### 카드 8. 제거

**할 일:** 같은 `packages` 배열에서 그 경로 한 줄을 지우고 senpi를 새로 엽니다.
**결과:** 라벨이 사라지고 Tab은 원래 동작으로 돌아갑니다. 기억 파일을 지우고 싶으면 `<agentDir>/primary-agents/memory/`를 지우면 됩니다. 이 확장은 omo.jsonc를 건드리지 않으므로 거기서 지울 것은 없습니다.

### 카드 9. 개발용 확인

**할 일:** 저장소에서 테스트를 돌립니다.

```
npm test
```

**결과:** 모든 테스트가 통과하고 끝에 `# fail 0`이 찍힙니다.

## 문제 해결

### 카드 10. Tab을 눌러도 안 바뀜

**확인할 것:**
1. 커서 앞 단어가 경로처럼 생겼는지 봅니다(`/`, `.`, `~`, `@`로 시작하거나 `/`, `\`를 품은 단어). 그렇다면 Tab은 완성입니다. 띄어쓰기 한 칸 뒤에 다시 누르세요.
2. 응답 중인지 봅니다. 끝난 뒤에 다시 누르세요.
3. 라벨이 아예 안 보이면 다른 확장이 입력창(editor)을 가져간 상태입니다. 그 확장을 끄거나 `/agent`로 바꾸세요.

### 카드 11. Hephaestus가 안 보이거나 건너뜀

**원인:** Hephaestus는 GPT 계열 모델만 씁니다. ChatGPT 구독이나 OpenAI 로그인이 없으면 쓸 수 없는 에이전트로 처리되어 건너뜁니다.
**할 일:** senpi에서 ChatGPT 구독(또는 OpenAI) 계정에 로그인한 뒤 새 세션을 엽니다.

## 검증 범위(정직하게)

기존 검증과 2026-10-21 복구 후보의 검증을 구분합니다. 후보 검증은 실사용 설치 완료가 아닙니다.

- 시나리오 S1~S15 가운데 **S12(실제 모델로 해 보는 설치 시험)는 돌리지 않았습니다.** todo 16의 실사용 설치 뒤에 합니다.
- 넓은 화면 시험(S3)은 200칸이 아니라 **155칸**에서 했습니다. Herdr 창의 최대 폭이 155칸입니다.
- 예전 프로필 화면의 미해결 결함은 복구 후보에서 수정됐습니다. 같은 화면 소스의 독립 검토 두 건과 252개 캡처가 통과했습니다. 이후 목록의 출처 해시가 갱신됐으며, 이 변경을 예전 화면 전체의 새 검토로 표현하지 않습니다.
- 후보는 확장 기억 파일을 읽기 전용으로 보여 줍니다. 파일이 없으면 기억 칸은 `-`입니다. 설정 화면은 확장의 기억 파일을 쓰지 않습니다.
- 예전 원본과 설치본의 바이트는 다릅니다. 소유자가 승인한 원본+기록된 별도 패치 대조는 9,062개 항목에서 설명되지 않는 차이 없이 통과했습니다. 옛 원본과 같아졌다는 뜻은 아닙니다.
- 새 검토 허용 정책은 실제 임시 TUI에서 확인했습니다. 요청·계획 파일이 없으면 거절하고, 프로메테우스의 말로 하는 재계획은 허용하며, 진행 중 자식이 같은 대화로 돌아오고 다시 실행해도 검토를 재잠금하지 않습니다. 최종 감사와 실사용 설치는 별도입니다.
